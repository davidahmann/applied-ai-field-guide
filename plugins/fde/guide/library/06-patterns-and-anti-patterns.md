# Production Patterns and Anti-Patterns

Canonical machine-readable catalog: [`patterns/pattern-catalog.json`](../patterns/pattern-catalog.json).

This is the implementation pattern library. Each pattern is phrased as a decision, not a framework preference. The evidence links point to the six-month research ledger, which records source quality and caveats.

## High-leverage patterns

| **Admit capabilities by verified digest** | A runtime loads a tool, MCP server, skill, CLI, or code package | Require signed provenance, a trusted registry decision, SBOM, exact interface digests, bounded authority, lifecycle ownership, and a tested disable path; intersect that authority with caller, tenant, handoff, and deployment policy at invocation | [R26-13](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-13), [R26-18](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-18), [R26-36](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-36), [R26-58](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-58), [R26-59](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-59) |
| **Attenuate authority at every handoff** | Work crosses an agent, worker, model, or context-reset boundary | Send a closed, signed, expiring, single-use envelope containing verified state, provenance, unresolved work, remaining budget, and terminal reason; reject any action, scope, effect, identity mode, depth, or budget beyond the parent ceiling | [R26-48](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-48), [R26-54](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-54), [R26-56](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-56) |
| **Validate operational knowledge before productizing it** | FDE or internal applied-AI work turns observations into context, rules, evaluation cases, or shared capability | Classify the item, validate it with its owner, preserve scope and provenance, decide whether to retain, repair, remove, escalate, or abstract it, and promote only sanitized recurrent patterns through normal release gates | [R26-37](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-37), [R26-41](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-41), [R26-45](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-45), [R26-56](../research/2026-02-07--2026-08-07-production-agent-source-ledger.md#r26-56) |

The capability-admission pattern applies SLSA and in-toto supply-chain mechanisms to agent capabilities; the exact manifest and authority intersection are repository-defined policy. The signing, expiry, nonce, replay, and strict-subset mechanics in the handoff pattern are likewise repository-defined enforcement under `CTX-005`; the cited agent sources support typed, stable handoffs but do not establish a universal wire format.

## Anti-patterns to reject in design review

| Anti-pattern | Why it fails | Replace it with |
| --- | --- | --- |
| **“The demo proves the use case.”** | Capability does not establish a baseline, adoption, production readiness, or realized value. | Observed current work, workflow charter, falsifiable value case, separate pilot gates, and stop conditions. |
| **“The FDE team will keep running it.”** | The customer never acquires domain, support, evaluation, release, incident, or change ownership. | Named receiving owners, paired operation, exercised handoff, and explicit delivery-team exit criteria. |
| **“Keep the custom sidecar; it ships faster.”** | A field-owned parallel stack bypasses normal architecture, security, release, telemetry, on-call, and lifecycle ownership, then becomes an unsupported shadow product. | An approved target or shared-product destination, normal engineering path, and a time-bounded migration or retirement plan. |
| **“Chat or a dashboard is the product.”** | Insight remains disconnected from the professional decision, governed action, persistent evidence, and outcome feedback. | A durable work artifact with local evidence, edit/interrupt/escalate controls, authorized action, and writeback. |
| **“Give it every tool so it can handle anything.”** | Tool definitions consume context, create selection ambiguity, and widen the attack surface. | Progressive discovery, task-scoped bundles, compact primitives, and a sandboxed general escape hatch. |
| **“The prompt says not to do that.”** | Prompt injection, tool output, and model drift can bypass instructions. | Deterministic authorization, sandbox limits, egress policy, write staging, and approval gates. |
| **“The page says success, so the task is done.”** | A click, banner, screenshot, or recording can be stale, misleading, duplicated, or disconnected from authoritative business state. | Keep visual evidence for debugging and complete only after a service receipt plus source-of-truth readback. |
| **“The sandbox has no direct Internet, so it is safe.”** | Proxies, package registries, trusted sidecars, and permitted tools can become escape or exfiltration paths. | Threat-model every outbound path, broker credentials, log anomalous behavior, and test containment. |
| **“The destination is allowlisted, so egress is safe.”** | An allowed host can still expose redirects, attacker credentials, public accounts, server-side fetches, or excessive data. | Bind egress to operation, resolved address, method, redirect, credential, account, tenant, request, and response policy. |
| **“The benchmark pass rate proves readiness.”** | Benchmarks can be irrelevant to the workflow or gameable by agents that share the evaluator's trust boundary. | Artifact and trajectory evaluation, evaluator isolation, real-world replay cases, and sampled human review. |
| **“One successful trial proves reliability.”** | Stochastic behavior, environment variance, and contamination make an unqualified score unstable. | Repeated isolated trials, product-matched aggregation, uncertainty, full version manifest, and contamination checks. |
| **“The agent reviewed its own work, so it is verified.”** | Shared context, assumptions, and incentives make self-review useful feedback but not independent release evidence. | Deterministic invariants, isolated evaluators or holdouts, and accountable human review where required. |
| **“Store the result as memory; we will fix it later.”** | Unapproved or poisoned conclusions compound through future runs. | Guardrail and approval gates before state persistence; provenance and invalidation rules. |
| **“Parallel agents will make it better.”** | Fan-out changes search behavior, creates duplicated effects, burns budget, and makes cancellation/merge semantics critical. | Explicit concurrency caps, idempotency keys, cancellation propagation, and confirmation runs. |
| **“One global success rate is enough.”** | Aggregate metrics hide poor performance on new or rare but consequential workflow classes. | Behavioral clustering, per-segment metrics, and regression cases for newly discovered patterns. |
| **“MCP is our workflow state machine.”** | Transport sessions, caches, and request IDs are not durable business state or approval history. | Keep workflow state in an explicit durable layer; use MCP as a scoped tool protocol. |
| **“The agent can access the same secrets as the service.”** | A prompt-injected model can read environment variables, files, logs, or configuration and exfiltrate them. | No model-visible secrets, dedicated workload identity, gateway-held credentials, and short-lived tokens. |
| **“Retry until done.”** | It turns uncertainty into unbounded cost, repeated unsafe actions, and opaque degradation. | Evidence-based exits, bounded retries, error taxonomy, escalation, and circuit breakers. |
| **“Ship first; add audit later.”** | Missing traces and provenance make incidents irreproducible and prevent trustworthy improvement. | Agent-native telemetry from the first controlled deployment. |
| **“The aggregate suite passed, so roll it out everywhere.”** | One model route, segment, policy, tool, or context configuration can regress under a healthy global average. | Per-route evidence, a versioned solution manifest, named canary, soak, kill switch, and rollback. |
| **“The package name and version are approved.”** | Names and mutable version labels do not prove publisher identity, artifact bytes, dependencies, or runtime authority. | Signed digest-bound admission, verified registry status, exact interface and SBOM checks, and fail-closed runtime authority intersection. |
| **“Just summarize the work for the next agent.”** | Free-form handoffs lose provenance and verified state, can smuggle instructions, reset budgets, and silently widen authority. | A typed, signed, expiring, single-use handoff envelope with scope, effect, identity, depth, and budget attenuation. |
| **“The graph says it is safe.”** | Generated relationships can be inferred, stale, incomplete, sensitive, or simply wrong; they cannot establish current authorization or task completion. | Treat the map as derived navigation, then use source policy, tool-boundary authorization, evaluation, approval, and readback. |

## Fast failure diagnosis

| Symptom | Most likely owning layer | First check |
| --- | --- | --- |
| Agent selected an irrelevant tool | Context/tool design | Scope, descriptions, tool loading, and task classification |
| Agent did the right action with the wrong authorization | Identity/policy | Caller identity propagation, per-tool scope, gateway decision |
| Agent appears successful but the business state is wrong | Verification/evaluation | Postcondition, source-of-truth readback, artifact integrity |
| Costs or latency spike unpredictably | Loop/concurrency | Retry budget, fan-out, cache behavior, tool wait, model routing |
| A new user workflow fails despite a good global metric | Observability/evaluation | Behavior cluster, missing replay case, hidden assumption |
| The system is technically healthy but users avoid it | Product/adoption | Workflow fit, evidence surface, review load, training, incentives, and support path |
| Activity grows but business value does not | Value/measurement | Eligible population, accepted outcomes, attribution, downstream rework, and full cost |
| Every operational question returns to the delivery team | Ownership/handoff | Named service owner, enablement evidence, release and incident exercises, exit criteria |
| A worker continues after another fails | Concurrency/durability | Cancellation propagation, idempotency, merge and rollback contract |
| Model output or telemetry becomes an instruction | Trust boundary | Taint handling, prompt injection control, content-to-action policy |

## The non-negotiable rule

**An LLM may propose an action; deterministic systems decide whether, with which identity, in which environment, and under what evidence it may execute.**
