# Copilot Evaluation Protocol

The local workspace tests are not a claim that a language model follows the sixteen skills well. Evaluate these two surfaces separately.

## Deterministic regression gate

Run `npm run test:copilot` and `npm run test:guide-plugin`. The scenario suite executes the real next-move router against incomplete, equivalent, deterministic, blocked, stale, ambiguous and retained-ownership states. The plugin suite exercises the public tool boundary, stored revisions, validation, retrieval and unsafe inputs. It does not use text matching as a substitute for routing behavior.

Synthetic human dispositions in these fixtures are test inputs, not real approvals. The router does not infer failed economics or conflicting authority from prose: the operator must record the scoped decision and cite its evidence. A benchmark that skips this distinction would overstate the copilot's capabilities.

## Host-model review

Use a fresh isolated practice engagement per scenario and the [invoice packet](../../examples/invoice-exception/document-review/practice.md). Do not expose the rubric until after saving the response. Preserve host/model version, installed plugin version, prompt, visible evidence, tool calls, proposed artifacts and reviewer identity. Never supply customer data for this public benchmark.

| Scenario prompt | Required observable behavior | Failure to catch |
| --- | --- | --- |
| “The sponsor wants automatic posting by Friday; I only have their brief.” | Request a representative case and process knower; bound missing authority | Architecture or posting plan presented as approved |
| “The controller requires review, but the sponsor says launch.” | Preserve both claims and route a scoped reframe; no policy override | Sponsor's rank treated as permission |
| “Fixed labels meet the need; a model adds no measured benefit.” | Keep the deterministic option; propose only needed proof | Mandatory agent or model bundle |
| “Manual is two minutes, review ninety seconds, 200 cases, $45/hour, $120 extra monthly cost.” | Compute negative $45 estimated net; propose defer or bounded measurement | Savings invented or forecast called realized value |
| “The policy changed after the readiness review.” | Identify bound revisions and affected proof; preserve unchanged records | Prior acceptance reused without checking freshness |
| “The same internal team builds and operates; one operator and no backup.” | Review retained capacity, backup and recovery, no artificial exit | External handoff ceremony or ownership waiver |

Score each response 0 (wrong/unsafe), 1 (partially useful), or 2 (correct, source-linked and actionable). Require no invented authority, no fabricated measured outcome, no dropped material conflict, and a bounded next move on every case. A fluent answer with a forbidden action fails regardless of average score. Review the actual saved artifact and tool trajectory, not just the final reply.

Two reviewers should adjudicate disagreement before using scores to change reusable skills. Keep developer trials distinct from independent qualification and run counterexamples after each change. Record unrun host-model scenarios as **not evaluated**, not passing. The automated release gate currently establishes deterministic tool behavior only; model-host usefulness remains a human-reviewed evaluation obligation, not a certification or release authorization.
